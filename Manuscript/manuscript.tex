%% an abstract and keywords
\Abstract{The analysis of multilevel data requires careful attention
when some measures are missing. A common strategy is to use imputation
and replace missing values with one or more plausible values. The
resulting datasets can then be analyzed using standard software
packages. Although numerous methods for multiple imputation have been
proposed, software implementations for multilevel data are still
relatively scarce.

In this tutorial, we introduce the key challenges of dealing with
(incomplete) multilevel data and illustrate how to impute them using the
\proglang{R} package \pkg{mice}. We explain how clustering can be
effectively addressed and describe methods for handling non-ignorable
missingness mechanisms. To make it easier to use the proposed methods,
we provide code snippets and relevant example data for three case
studies.

First, we estimate the association between the pupils' sex and their
popularity score in data on 2000 pupils' popularity in 100 schools.
Second, we estimate the prognostic value of Computerized Tomography on
6-month mortality in data on 11,002 patients across 15 studies on
traumatic brain injuries with data Missing At Random. Third, we estimate
the association between family obesity and BMI in data on 2,111 patients
from 5 regions with data Missing Not At Random.}

\hypertarget{sec-intro}{%
\section{Introduction}\label{sec-intro}}

Missing data frequently occurs in observational studies, and to a lesser
extent in experimental studies, like Randomized Controlled Trials
(RCTs). Dealing with incomplete, requires careful consideration, not
only of assumptions about the cause of the missing data, but also of
those intrinsic to the main analysis of the study. This is necessary to
prevent biased estimates and reduced statistical power, which could
ultimately lead in the end to erroneous study conclusions.

Many studies are based on inherently clustered data. For example, RCTs
and observational studies often involve patients sampled from multiple
sites, such as countries or counties. Electronic Health Records datasets
frequently collect information from multiple hospitals, and some studies
even rely on aggregate data from multiple studies, such as Individual
Participant Data (IPD).

Commonly, these studies face two simultaneous challenges: 1) the cluster
structure and 2) missing data. The observations within clusters are not
independent, which requires the use of multilevel modeling techniques in
the main analysis to account for the hierarchical structure within the
data. This structure must also be considered when dealing with missing
data, as several imputation methods are based on models with implicit
assumptions. Therefore, we will briefly explain the concepts of both
cluster structure and missing data, and discuss why their presence can
be problematic.

This manuscript serves as a tutorial for imputing incomplete multilevel
data using the \pkg{mice} (Multivariate Imputation by Chained Equations)
package in \proglang{R}. \pkg{mice} has emerged as the de facto standard
for imputation via chained equations, which addresses missingness
iteratively on a variable-by-variable basis. It is recognized for
producing valid inferences across a range of missing data scenarios
\citep{buur18}.

We provide a practical guide and code snippets for various missing data
scenarios, encompassing non-ignorable mechanisms. Through three case
studies from the fields of social and biomedical sciences, we demostrate
the practical use of software tools for this purpose. For brevity, our
focus lies exclusively on multilevel imputation via chained equations
with \pkg{mice}; other imputation methods and packages (e.g., \pkg{jomo}
\citet{grun18}, \pkg{smcfcs} \citet{smcfcs}, \pkg{mdmb} \citet{mdmb})
fall beyond the scope of this tutorial. We only consider hierarchical
data with two levels, and we also assume basic familiarity with the
notation for the hierarchical models in the \proglang{R} packages
\pkg{lme4} \citet{lme4} and \pkg{nlme} \citet{nlme}.

\hypertarget{sec-2conmulti}{%
\subsection{Concepts in multilevel data}\label{sec-2conmulti}}

Many datasets include individuals that are clustered together, for
example in geographic regions, or different studies. In the simplest
case, individuals (e.g., students) are nested within a single level of
cluster (e.g., school classes). More complex clustered structures may
occur when there are multiple hierarchical levels (e.g., students in
classes in different schools or patients in hospitals in regions across
countries), or when the clustering is non-nested (e.g., electronic
health record data from diverse settings and populations within large
databases).

With clustered data we generally assume that individuals from the same
cluster tend to be more similar than individuals from other clusters. In
statistical terms, this implies that observations from the same cluster
are not independent and may, in fact, be correlated. If this correlation
is left unaddressed, estimates of \emph{p}-values, confidence intervals,
and model parameters are prone to bias \citep{loca01}. Statistical
methods for clustered data typically adopt hierarchical models that
explicitly describe the grouping of observations. These models are also
known as `multilevel models', `hierarchical models', `mixed effect
models', `random effect models', and in the context of time-to-event
data as `frailty models'. Box \ref{nte-multilevel-data} provides an
overview of multilevel data and Box \ref{nte-multilevel-model} provides
an overview of some key concepts in multilevel modeling.

\begin{tcolorbox}[enhanced jigsaw, bottomrule=.15mm, leftrule=.75mm, arc=.35mm, rightrule=.15mm, breakable, colback=white, left=2mm, opacityback=0, toprule=.15mm]

\textbf{Box 1: Hierarchical data}\vspace{2mm}

Data are grouped into clusters at different levels, observations
belonging to the same cluster are expected to share certain
characteristics. We can specify:

\begin{itemize}
\tightlist
\item
  \textbf{Sample units:} units of the population from which measurements
  are taken in a sample, e.g., student or patient.
\item
  \textbf{Cluster:} variable that specify the cluster or grouping, e.g.,
  classroom or hospital.
\item
  \textbf{Level-1 variable:} variable that varies within a cluster,
  e.g., test score.
\item
  \textbf{Level-2 variable:} variable that does not vary within a
  cluster but between clusters, e.g., teacher experience or geographical
  region of the hospital.
\end{itemize}

\end{tcolorbox}

\begin{tcolorbox}[enhanced jigsaw, bottomrule=.15mm, leftrule=.75mm, arc=.35mm, rightrule=.15mm, breakable, colback=white, left=2mm, opacityback=0, toprule=.15mm]

\textbf{Box 2: Hierarchical model}\vspace{2mm}

A hierarchical (multilevel) model is a statistical model appropriate for
situations where observations are organized at more than one level
(e.g., groups). This type of model recognizes and explicitly accounts
for the potential correlation of observations within these groupings,
addressing the dependencies that often violate the independence
assumption between observation of traditional regression models. To
achieve this, hierarchical models may incorporate fixed or random
effects:

\begin{itemize}
\tightlist
\item
  \textbf{Fixed effect:} Also called a common effect is an effect that
  is assumed to be constant across all sample units, e.g., gender effect
  that is the same for all classes or hospitals.
\item
  \textbf{Random effect:} Effects that are a source of random variation
  in the data, and whose levels are sampled from a distribution. e.g.,
  the test score may vary between classrooms or hospitals due to
  uncontrolled factors such as the teacher experience or quality of
  hospital protocols.
\end{itemize}

In \proglang{R}, hierarchical models can be fitted using packages such
as \pkg{lme4} \cite{lme4} or \pkg{nlme} \cite{nlme}. In addition to
random intercepts, multilevel models can also include random slopes and
heterogeneous residual variances across clusters (see e.g.,
\cite{gelm06, hox17, jong21}).

The variability due to clustering is often measured by the
\textbf{intraclass correlation (ICC)}, which in simple terms describes
how similar the units in the same cluster are.

\end{tcolorbox}

\hypertarget{sec-2conmis}{%
\subsection{Concepts in missing data}\label{sec-2conmis}}

In a study, any variable can have missing values, including those in the
main model, such as exposures, outcomes, and confounders, as well on
other variables, such as \textbf{auxiliary} variables, which, although
not explicitly in the analysis model, can improve the imputation of
missing values.

These incomplete variables can be categorized by a
\textbf{missingness pattern} that describes how observed and missing
values are arranged in the dataset. There are different types of missing
patterns such as univariate, monotone, and file matching \cite{buur18}
(\(\S\) 4.1). Specifically for clustered data, we highlight the
difference between sporadic and systematic patterns. Sporadic
missingness arises when variables are missing for some but not all of
the units in a cluster \cite{jola18}. For example, it is possible that
test results are missing for several students in one or more classes.
When all observations are missing within one or more clusters, data are
said to be systematically missing. These missingness patterns are
visualized in Figure~\ref{fig-spod}, where the column \(X_1\) is
completely observed, column \(X_2\) is systematically missing in cluster
2, and column \(X_3\) is sporadically missing.

\begin{figure}[h]

{\centering \includegraphics{manuscript_files/figure-pdf/fig-spod-1.pdf}

}

\caption{\label{fig-spod}Sporadic and Systematic Missigness}

\end{figure}

To analyze these incomplete data, we have to take the nature of the
missingness and the cluster structure into account. For example, the
sporadic missingness in \(X_3\) could be easily amended if this would be
a level-2 variable (and thus constant within clusters). We could then
extrapolate the true (but missing) value of \(X_3\) for unit 1 from unit
2, and the value for unit 4 from unit 3. If \(X_3\) would instead be a
level-1 variable (which may vary within clusters), we could not just
recover the unobserved `truth', but would need to use a stochastic
imputation data method, or discard the incomplete units altogether
(i.e., complete case analysis, CCA).

CCA may introduce bias when the observed values are not a random sample
of the population. For example, in a clinical trial comparing a new
treatment with a standard or reference treatment, some participants
receiving the new treatment may drop out due to side effects. If the
sickest patients have the most side effects, then the sickest patients
are excluded under CCA, resulting in a selection bias in which the
effect of the new treatment is overestimated. Moreover, reducing the
sample size can impede the estimation procedure of the main model,
leading to inefficient estimations and reduced statistical power. This
can potentially impacting the conclusions drawn from hypothesis tests.

Apart from CCA, there are several strategies that can be used to handle
missing data, such as maximum likelihood, Bayesian estimation and
imputation. Imputation, in particular, separates the missing data
problem from the analysis, allowing the completed data to be analyzed as
if it were completely observed. It is generally recommended to impute
the missing values more than once (multiple imputation) in order to
preserve uncertainty due to missingness and to allow for valid
inferences \cite{rubin76}.

Imputing missing data requires consideration of the mechanism behind the
missingness. Rubin proposed to distinguish between data that are missing
completely at random (MCAR), data that are missing at random (MAR) and
data that are missing not at random (MNAR; see Box \ref{nte-box-mech}).
For each of these three missingness generating mechanisms, different
imputation strategies are warranted (\cite{yuce08,hox15}).

In this manuscript, we focus on the multiple imputation (MI) approach
using the fully conditional specification (FCS). This approach is
popular, easy-to-use and it can be applied to various types of
incomplete variables and missingness patterns. The \proglang{R}
\pkg{mice} package implements this approach. It assumes MAR by default,
but it can also be extended to certain MNAR data.

MI assumes that data follow a multivariate distribution, so incomplete
values for each variable are imputed or filled in with draws from this
distribution. The FCS approach relaxes this assumption by specifying the
multivariate distribution through conditional distributions. The
procedure generates imputed values for each variable iteratively, where
an \textbf{imputation method} needs to be specified for each incomplete
variable, conditional on other variables included in the dataset.

\pkg{MICE} and other \pkg{MICE}-based packages offer a variety of
parametric methods that implicitly assume a (statistical)
\textbf{imputation model}, as well as non-parametric methods such as
Predictive Mean Matching (PMM), Random Forest, or k-Nearest Neighbors
(k-NN) to generate the imputed values. These methods can be used for
single-level data (defined as 1L methods) as well hierarchical data with
two levels (2L methods) or more \cite{grun18}.

After the imputation procedure (or \textbf{imputation step}), multiple
complete datasets, say M in total, are obtained, with missing values
filled in with plausible values. Then, in an \textbf{estimation step},
the main model or estimation procedure of the study is applied to each
of the M complete datasets. Finally, in a \textbf{pooling step}, the
results of the M analyses, usually point estimates and their standard
errors, are combined into a single result using Rubin's
rules.\cite{rubin1987}

\hypertarget{sec-2strat}{%
\section{Multilevel imputation strategies}\label{sec-2strat}}

In hierarchical incomplete data, the use of imputation strategies that
ignore clustering, i.e., 1L methods, might result in biased parameter
estimates and underestimation of the between-cluster variance, leading
to inflated Type I error rates, especially when the true intra-class
correlation (ICC) is large (ICC \textgreater{} 0.1).
\cite{taljaard2008,ende16}. They can only be used when the proportion of
missingness (less 5\%) and the ICC are low ( \textless{} .1)
\cite{grun18}. Therefore, it is crucial to utilize strategies that
account for clustering, such as the use of a cluster indicator, which is
employing imputation separated by clusters, or adopting multilevel
imputation methods (2l-method) \cite{eddingsa}.

In the \textbf{cluster indicator} strategy, the cluster variable
(transformed internally by \pkg{mice} to dummy variables) serves as a
predictor using 1L imputation methods. This implies that all variability
between clusters is attributed to the cluster, rendering the inclusion
of level 2 variables unnecessary in the prediction model
\cite{mcneish2019}. This strategy performs well in datasets with few
clusters and numerous observations per cluster \cite{graham2009}. It can
be used for estimation of hierarchical model parameters when the
primarily interest of the study are the fixed effects. However, since
the imputed values per cluster are biased towards the cluster mean, it
may lead to overestimation of the between-cluster variance and an
inflation of the Type II error, particularly when the true ICC is small
(ICC \textless{} 0.1), the percentage of missingness is large, and with
small cluster sizes \cite{andridge2011,drec15}.

In the \textbf{separate cluster imputation} strategy, the data set is
divided into subdatasets according to the cluster variable. Then,
imputations are separately performed on each subdataset, and combined
(e.g., using the \code{rbind} function) in one imputation object that is
finally used in the main analysis. As the imputation models are
independently estimated in each cluster, and in some cases may use
different predictors, e.g., when a predictor variable is systematically
missing as the information was not collected in a group. Similar to the
cluster indicator approach, this method could lead to an overestimation
of the variance between clusters in the estimation of a hierarchical
model and, therefore, a reduction in power. \%This strategy is sometimes
used when the interaction term between variables is of special interest
in the main analysis, for example, the interaction between a treatment
and a group \cite{buur18}.

In the strategy that employs \textbf{multilevel imputation methods}, 2L
methods are used. These 2L methods have been developed to internally
account for the hierarchical structure of the data, which allows for
obtaining proper estimates of the fixed effects and the variance
components of the hierarchical model \cite{speidel2018}. The 2l methods
include \textbf{1-stage methods}, where a hierarchical model is
estimated using the complete observations. This model associates the
target variable (to be imputed) with a set of predictor variables,
incorporating both fixed and random effects. While these methods tend to
perform better for balanced data, their performance may be compromised
when the number of clusters is insufficient to accurately estimate the
hierarchical model \cite{grun18}.

Additionally, there are \textbf{2-stage methods} where the imputation
model is estimated in two steps. In the first step, a model (e.g., a
generalized linear model) is estimated for each cluster based on the
complete observations, and in the second step, the parameters of the
models for each cluster are combined using meta-analysis techniques to
obtain a model with pooled parameters, which serves as the basis for
imputing missing values. Some of the 2L methods used in \code{mice} are
detailed in the Annex Table \ref{tbl-annex-2lmethods}

It has been recommended that the imputation strategy should align with
the main (study analysis) model, commonly referred to as congeniality
\cite{meng1994}. Hence, it's vital to carefully evaluate the assumptions
of each method and compare them with those of the main model. This
includes considerations such as assumptions about the distribution of
the outcome model, inclusion of interaction terms, and homoscedasticity
(equal error variance across clusters). However, it's essential to
examine the information provided by the data and determine if it
sufficiently meets the requirements imposed by the imputation method,
taking into account factors like sample size, number of clusters, and
missing patterns (e.g., systematic missingness). Additionally, it's
worth considering whether a complex imputation model is suitable for the
data, as less complex strategies may also yield unbiased estimates in
specific scenarios \cite{bailey2020}.

\hypertarget{imputation-workflow}{%
\section{Imputation workflow}\label{imputation-workflow}}

Below, an imputation workflow is described that can be generally used to
impute multilevel data. A brief description of each step is provided,
along with general recommendations about the technical procedure.

\hypertarget{pre-imputation}{%
\subsection{Pre-imputation}\label{pre-imputation}}

First, the variables in the data set should be clearly identified in
terms of their hierarchical type (level-1, level-2 or cluster) and
variable type (continuous, binary, factor, count). This step will help
to select the appropriate imputation method for each type of variable,
to correctly specify and include the variables in \code{mice}, and to
ensure consistency in the format of the variables across all clusters.

Next, the observed data should be characterized. We can use a density
plot for each cluster or spaghetti plots to understand if the intended
main analysis is appropriate for the data (e.g., random intercept vs.~a
random slope model). Additionally, the ICC should be examined to assess
the cluster differences and to select the most convenient imputation
strategy (such as cluster indicator versus hierarchical methods). Then,
the missingness should be characterized using visual tools such as
\pkg{ggmice} \cite{ggmice2023}. Constructing missingness pattern plots
and missingness percentage plots per cluster is recommended to identify
the information available at each cluster and also to select the most
appropriate imputation method.

When preparing the dataset for imputation, it should be ensured that all
essential variables required for the main analysis are included, such as
the exposure or intervention, outcome, covariates, confounders,
stratification factors, the cluster variable, and sample unit ID.
Additionally, other useful variables, such as instrumental or auxiliary
variables, should be considered for inclusion, which may enhance the
accuracy of the imputation model.

Auxiliary variables with a high proportion of missing data may have
minimal impact on the imputation model and could mitigate the risk of
multicollinearity or computational issues, especially with certain
parametric imputation methods. Therefore, the selection of auxiliary
variables should be guided by the association between the incomplete
variable and predictor variables, using correlation statistics, as well
as the potential contribution of one variable to impute another, using
missingness pattern statistics such as the influx and outflux criteria.
The inflow criteria quantify the connections between missing data in one
variable and observed data in others, while the outflow criteria measure
the connections between observed values in one variable and missing data
in others \cite{buur18} (\(\S\) 4.1.3).

Finally, before imputation is undertaken, we should assess if the
estimation procedure is robust to missing data, i.e., if the main model
can handle missing data. Sometimes, simpler methods like complete case
analysis might suffice, especially if the missingness is low (usually
\textless5\%). There are scenarios in which specific Maximum Likelihood
(ML) estimation methods outperform Multiple Imputation (MI) methods. For
instance, when the response variable is the only incomplete variable,
mixed models demonstrate robustness to missing data under the MAR
assumption and with a correct variance-covariance specification
\cite{molenberghs2007}.

\hypertarget{imputation}{%
\subsection{Imputation}\label{imputation}}

\hypertarget{choice-of-individual-imputation-methods}{%
\subsubsection{Choice of individual imputation
methods}\label{choice-of-individual-imputation-methods}}

The imputation model for each incomplete variable in the dataset should
be chosen first. The mice package provides a range of imputation methods
designed specifically for hierarchical data (See Annex, Table
\ref{tbl-annex-2lmethods}). Notable among these are \pkg{jomo}
\cite{jomo}, \pkg{micemd} \cite{micemd}, and \pkg{pan}
\cite{schafer2002}. For a comparison of these methods for addressing
variables with systematic and sporadic missingness, see
\cite{audigier2018}.

The \code{make.method} function in \pkg{mice} suggests the most
plausible 1L imputation method for incomplete variables according to
their type (continuous, binary, categorical). However, modifications are
required for clustered data and when the type variable is not aligned
with the data (e.g., some skewed continuous variables are better imputed
with pmm methods).

To address level-2 variables, the \pkg{micemd} package offers the
\code{find.defaultMethod} function. This function assists in selecting a
2L imputation method from the \pkg{micemd} methods based on cluster
size, the proportion of missing data in each cluster, and the variable
class. For level-2 variables, the same value needs to be assigned to all
units in the cluster. This can be achieved by specific methods where
separate imputations are performed for level-1 and level-2 variables.
\cite{grun18}

Besides the package-defined imputation methods, custom methods can be
specified using the ``I formula.'' This allows deterministic variables
to be calculated during the imputation or the imputation methods to be
tweaked based on specific conditions, such as conditioning the
imputation model to the level of an incomplete covariate (e.g., a
pregnancy test for females). \textbf{Deductive imputation} is used to
impute values that can be deterministically deducted from other
variables using logical rules or formulas, such as BMI from weight and
height. This can also be useful for getting values for level-1 variables
from level-2 ones, like in IPD from multiple studies. For example,
deductive imputation can be employed to infer missing test values for
patients associated with a centre unit that lacks a test procedure or
machine, considering accessible metadata or protocol details.

\hypertarget{model-specification}{%
\subsubsection{Model specification}\label{model-specification}}

The imputation model for each incomplete variable must be aligned with
the main (substantive) model. Therefore, it should be ensured that the
imputation model shares the assumptions with the main model, such as the
treatment of clustering, the inclusion of non-linear or interaction
terms, and variable transformations.

However, the imputation model can include additional variables without
causing compatibility issues. For example, it's recommended to include
the outcome variable in the imputation model for predictor variables
\cite{moons2006}. If the outcome is time-to-event, the Nelson-Aalen
estimate of the time to the event and the event indicator should be
added as covariates in the imputation model \cite{white2009}. Also,
including auxiliary variables associated with the probability of missing
data may enhance estimation efficiency \cite{hardt2012}.

Imputation models are specified on a incomplete variable basis, either
using a prediction matrix in the \code{pred} parameter or through a list
of formulas in the \code{formula} parameter. In the prediction matrix
option, the prediction code of each predictor variable is specified for
each incomplete variable using predictor codes (see Box 4). On the other
hand, the formula option is useful in specifying complex imputation
models with polynomial terms or interactions and compared with the
prediction matrix method do not require the inclusion of additional
terms as Just Another Variable (JAV) \cite{buur18} (\(\S\) 6.4).

Recipes have been proposed for setting the imputation models of
incomplete level-1 and level-2 variables \cite{buur18} (\(\S\) 7.10).
These guidelines can be convenient to follow when the main model is
complex, such as those with interaction terms at different levels.
Following these recipes helps mitigate convergence problems that may
arise due to over-specification in the imputation model and ensures
compatibility among the conditionally specified imputation models, as
well as congeniality between the imputation model and the main model.
However, they can not be applicable to all 2l imputation methods. For
instance, the \code{2l.2stage} imputation methods of the \pkg{micemd}
package only allow the inclusion of random predictor variables
(prediction code = 2).

\hypertarget{issues-during-imputation}{%
\subsection{Issues during imputation}\label{issues-during-imputation}}

During the imputation process, certain issues may arise that halt the
process. In hierarchical model imputations, many issues are related to
over-fitting the imputation model. To troubleshoot, it is recommended to
inspect the imputation log file for variables causing problems. One
approach to address this is to reduce the number of predictors by using
functions like \code{quickpred} or by applying the previously referred
recipes step by step.

Another option is to consider variable transformations, such as
centering within clusters, and scaling when the model is invariant to
linear transformations e.g., random intercept models. Also, adjusting
the level of the hierarchical model (e.g., using a homogeneous variance
imputation method) might also be beneficial.

It is crucial to check the range of imputed variables, as excessively
large imputed values for one predictor may trigger convergence issues in
other variables. To tackle this, including post-processing
specifications on problematic variables or utilizing imputation models
like Predicted Mean Matching (PMM) can ensure that imputed values align
with observable values.

In some situations, adopting a separate imputations strategy per study
objective might be worth considering. For example, in analyses involving
multiple endpoints, conducting distinct imputation processes for each
endpoint could be more effective than a unified imputation approach.

\hypertarget{convergence-and-sensitivity-analysis}{%
\subsection{Convergence and Sensitivity
Analysis}\label{convergence-and-sensitivity-analysis}}

Before starting the analysis of each imputed dataset, it is crucial to
validate the convergence of the imputation process. This is commonly
accomplished through trace plots that depict the mean and variance of
the incomplete variables across iterations. These plots serve to uncover
the need for additional iterations and also to identify potential
circular dependencies, i.e., when the missing part of a variable
\(X^{miss}\) depends on the missing part of another variable
\(Z^{miss}\), which in turn depends on \(X^{miss}\). Additionally, it is
also important to verify that imputed values fall within a plausible
range and also to check the distribution of imputed variables, ensuring
that the imputed variable distribution aligns with the distribution of
observed values (under the MAR assumption). An alternative approach
involves assessing the prediction accuracy of the imputation method
\cite{cai2023}.

While the majority of \pkg{MICE} methods are based on MAR assumptions,
field expert input may suggest that the MNAR mechanism could be
plausible for certain variables. An MNAR variable is one in which the
probability of missingness depends on an unobservable variable. This can
occur when missingness is associated with the incomplete value itself
(self-marking) or when there is an unobserved variable linked to both
the value and the probability of missingness of the incomplete value
(indirectly non-informative). Specifically, for the indirectly
non-informative case in hierarchical datasets, imputation methods based
on the Heckman method can be considered
\cite{hammon2020,hammon2022,munoz2023b}.

\hypertarget{main-analysis}{%
\subsection{Main analysis}\label{main-analysis}}

Finally, after verifying the imputation process, the main analysis is
performed on each of the M imputation datasets from the mice output.
These calculations can be done manually or easily by passing the mice
output object directly into the multilevel model functions of the
\pkg{nlme} or \pkg{lme4} packages.

Then, the model parameters of each imputed dataset are pooled following
Rubin's rules \cite{rubin1987}, which have already been implemented in
\proglang{R} functions such as \code{pool} from the \pkg{broom.mixed}
package \cite{broom.mixed} or \code{testEstimates} from the \pkg{mitml}
package \cite{mitml2023}.

\hypertarget{sec-illustrations}{%
\section{Case studies}\label{sec-illustrations}}

In this section, we will go over the different steps involved in
imputing incomplete multilevel data using the \code{mice} package.
Initially, we illustrate how to apply multiple imputation strategies on
the \code{impact} data. Then, using the popular data, we demonstrate how
to apply the 1-stage 2L imputation methods along with the application of
recipes for interaction terms. Finally, with the obesity data, we apply
the 2-stage imputation methods and show how to extend these methods in
the case of MNAR data.

\hypertarget{sec-2impact}{%
\subsection{Application of multilevel imputation strategies in
Impact}\label{sec-2impact}}

The first case study uses the \code{impact} dataset, which gathers
information from 15 studies containing the patient mortality after
suffering from traumatic brain injury (TBI) and some admission
information values. The dataset includes the following 11 variables:

\begin{itemize}
\tightlist
\item
  \code{id} Patient id,
\item
  \code{name} Name of the study,
\item
  \code{type} Type of study (RCT: randomized controlled trial, OBS:
  observational cohort),
\item
  \code{age} Age of the patient,
\item
  \code{motor\_score} Glasgow Coma Scale motor score, factor with 4
  levels,
\item
  \code{pupil} Pupillary reactivity, factor with 3 levels,
\item
  \code{ct} Marshall Computerized Tomography classification, factor with
  3 levels,
\item
  \code{hypox} Hypoxia (0=no, 1=yes),
\item
  \code{hypots} Hypotension (0=no, 1=yes),
\item
  \code{tsah} Traumatic subarachnoid hemorrhage (0=no, 1=yes),
\item
  \code{edh} Epidural hematoma (0=no, 1=yes),
\item
  \code{mort} 6-month mortality (0=alive, 1=dead).
\end{itemize}

This data was previously used by \cite{steyerberg2008a,steyerberg2019},
where models of different complexity were estimated to predict 6-month
mortality using the admission information of patients. For simplicity,
we considered the common effect approach with respect to the predictor
effects \(\beta\), where the intercepts \(\alpha\) vary between
clusters, but the predictor effects \(\beta\) are constant. The
prediction (main) model uses age,motor\_score, pupil reactivity, and CT
as predictors, being the model for the \(i\)-th patient from the
\(j\)-th study is given as:

\begin{align*}
 mort_{ij}& = Bernoulli(p_{ij})\\
logit(p_{ij})&=
\alpha_j +  \beta_1age_{ij}+ \beta_2motor\_score_{ij} + \beta_3pupil_{ij} + \beta_4ct_{ij}
\label{eqn:2mod0} \tag{main model : 1}
\end{align*} Here, \(\alpha_j\) is the main effect of the cluster j and
the effects \(\beta_1\), \(\beta_2\), \(\beta_3\) and \(\beta_4\) are
assumed constant across the clusters.

predictor variables. For instance, the ``id'' variable should not be
used for imputation, as it has no predictive value for imputation, but
we still we need to include the variable in the imputation dataset as
afterwards it will be used for the identification of each observation.

Also, as differences between clusters will be explained solely by the
cluster variable ``name,'' the variations at level-2 are meaningless and
should not be included in the imputation model. Therefore, we need to
remove the level-2 variable ``type'', and the level-1 variable ``id'' as
follows:

\begin{verbatim}
pred[ , c("id","type")] <- 0
\end{verbatim}

At times, the predictor matrix can be constructed using the quickpred()
function, which employs a variable selection procedure based on the
correlation between the target missing variable and potential predictor
variables in the dataset \cite{buur18}(\(\S\) 9.1.6). However, it's
crucial to verify the output of this function, as it may sometimes
result in imputation models for the outcome variable that lack essential
variables, have a limited list of predictors, or contain inconsistent
hierarchical terms, for instance, interaction terms without the
inclusion of the main effects. To prevent essential variables from being
excluded, include them with the ``include'' argument.

Then, we construct the `visit' vector, to specify the order in which
incomplete variables are imputed. Here, we ordered according to the
missing percentage.

\begin{verbatim}
visit <- c("pupil","hypots","tsah","edh","hypox","ct")
\end{verbatim}

Next, we proceed to impute the data by setting the \code{meth} and
\code{pred} and \code{visit} parameters in the \code{mice} function. The
output is a \code{mice} object that can be passed on to \pkg{mice}
package functions and other package functions such as functions from the
modeling packages \pkg{lme4} and \pkg{nlme}.

\begin{verbatim}
impcind <- mice(dati, pred = pred, meth = meth, visit = visit) 
\end{verbatim}

The cluster imputation strategy might suffice for the considered main
model. The separate cluster imputation strategy might be applied also,
but it might not be congenial with the main model as this imputation
strategy assumes that \(\beta\) effects vary across clusters, which
differs from the main model common effect.

If further complexities are taken into account in the study, such as
assuming that studies are randomly selected and that intercepts follow a
random distribution (random intercept), the main model would be
represented instead as:

\begin{align*}
 mort_{ij}& = Bernoulli(p_{ij})\\
logit(p_{ij})&= \alpha_j +  \beta_1age_{ij}+ \beta_2motor\_score_{ij} + \beta_3pupil_{ij} + \beta_4ct_{ij}\\\label{eqn:2mod1} \tag{main model : 2}
\alpha_j &\sim N(\alpha,\tau^2) 
\end{align*}

where \(\alpha\) is the overall intercept and \(\tau^2\) the
between-study variance. In this scenario, the complexity of the
imputation model should be increased by employing a 2l.model, thus
facilitating a congenial model with the \ref{eqn:2mod1} and avoiding
bias in the variance components \cite{speidel2018}. For brevity, the
code for these three strategies is included in the annex.

\hypertarget{sec:2pop}{%
\subsection{Illustration of one-stage imputation in the Popularity
data}\label{sec:2pop}}

For the second study case, we focus on demonstrating the imputation of
clustered data using 1-stage 2L methods, which are based on a
(generalized) linear mixed model simultaneously estimated across
clusters. We consider the simulated `popmis' dataset, which includes
pupils (\(n=2000\)) clustered within schools \((N=100)\). The following
variables are of primary interest:

\begin{itemize}
\tightlist
\item
  \textbf{pupil}, pupil identifier within the school.\\
\item
  \textbf{school}, school identification number;
\item
  \textbf{popular}, pupil popularity, self-rating between 0 and 10;
\item
  \textbf{sex}, pupil sex with levels 0 = boy, 1 = girl;
\item
  \textbf{texp}, teacher experience in years;
\item
  \textbf{teachpop}, teacher popularity rate given by the pupils.
\end{itemize}

The objective of this study is to develop a prediction model for pupil
popularity, that accounts for heterogeneity between schools. The main
analysis of the dataset will employ a hierarchical model, specifically a
multivariable regression with random intercepts and slopes for the
different schools, where estimates the popularity of the \(j\)-th
student belonging to the \(i\)-th school based on the gender of the
student, the teacher's experience, and the teacher's popularity as
follows: \begin{align*}
popular_{ij} &= (\beta_0 + b_{0i}) + \beta_1sex_{ij}+ \beta_2texp_{ij}\\
&+ (\beta_3+b_{3i})teachpop_{ij} + \beta_4 texp_{ij}*teachpop_{ij}+ \epsilon_{ij}
\end{align*}

where \(\beta_0\),\(\beta_1\),\(\beta_2\),\(\beta_3\) and \(\beta_4\)
are the fixed effects, \(b_{0i}\) is the random intercept effect and
\(b_{3i}\) is the random slope effect of teacher's popularity
distributed as

\(\begin{bmatrix}b_0\\b_3\end{bmatrix}\sim N\left(\begin{bmatrix}0\\0\end{bmatrix},\begin{bmatrix}\tau_0^2 & \rho\tau_0\tau_3\\\rho\tau_0\tau_3 & \tau_3^2\end{bmatrix}\right)\),
\(\tau_0^2\) and \(\tau_3^2\) are respectively the intercept and slope
variances and \(\rho\) the correlation of the random effects. The
\(\epsilon_{ij}\) denotes the error term distributed as
\(\epsilon_{ij}\sim N(0,\sigma^2)\), with population variance
\(\sigma^2\).

This hierarchical approach enables us to simultaneously consider
individual-level factors (such as gender) and school-level factors (such
as teacher experience), providing a comprehensive understanding of their
influence and interactions on pupil popularity scores.

\subsubsection{Imputation}\label{imputation-2}}

As before, we create the method vector with the \code{make.method}
function.

\begin{verbatim}
meth <- mice::make.method(popmis_amputed)
meth
\end{verbatim}

\begin{verbatim}
        pupil        school       popular           sex          texp 
           ""            ""         "pmm"            ""         "pmm" 
     teachpop teachpop.texp 
        "pmm"      "logreg" 
\end{verbatim}

This function suggests imputing all the incomplete variables using the
predictive mean matching method (pmm), except for the interaction term
`teachpop.texp'. However, this function does not support 2l.methods yet.
Therefore, manual modification of the methods is necessary. For the
level-1 variables (popular, teachpop), we can use the `2l.pmm' method
from the \code{miceadds} package. For the level-2 variable (texp), the
`2lonly.mean' method can be applied due to sporadic missingness within
clusters. Finally, for the `teachpop.texp' variable, specifying the
interaction can be achieved using the I notation as follows:

\begin{verbatim}
library("miceadds")
meth[c("popular","teachpop")] <- "2l.pmm"
meth["texp"] <- "2lonly.mean"
meth[c("teachpop.texp")] <- "I(teachpop*texp)"
\end{verbatim}

Next, we need to set the prediction matrix. Here we follow the recipes
for hierarchical datasets provided by \cite{buur18} (\$\S\$7.10) as the
main model involves interaction at different levels. Therefore, we start
by creating a predictor matrix using the make.predictor() function.
Initially, we will set a blank matrix where no predictor is assigned in
any of the prediction models (denoted as prediction code = 0, see Box
\ref{nte-box-pred}). Then we proceed to specify the cluster variable
(prediction code = -2) across all the imputation models.

\begin{verbatim}
pred <- make.predictorMatrix(popmis_amputed)
pred[,] <- 0
pred[,"school"] <- -2
\end{verbatim}

We define the imputation model of the outcome using the main model.
Specifically, we include the `texp' level-2 variable as a fixed effect
(prediction code = 1). The `sex' variable is also included as a fixed
effect in the main model. As suggested by recipes (\cite{buur18}),
include the group mean of the variable (prediction code = 3) to avoid
convergence problems. Additionally, we include the `teachpop' variable,
which requires a random slope in the main model, along with its group
mean (prediction code = 4). Finally, we add the cross-interaction term
as a fixed effect (prediction code = 1).

\begin{verbatim}
pred["popular",c("sex","texp","teachpop","teachpop.texp")] <- c(3,1,4,1)
\end{verbatim}

The imputation model of the interaction terms is specified with the
variables used for its deterministic imputation:

\begin{verbatim}
pred["teachpop.texp",c("texp","teachpop")] <- c(1,1)
\end{verbatim}

Additionally, we define the imputation model for other incomplete
variables by incorporating the group mean and avoiding circular
dependencies. For example, we refrain from including predictor variables
in the imputation model that were deterministically imputed with the
incomplete variable under consideration. In essence, we avoid using
interaction terms such as \texttt{teachpop.texp} in the imputation model
for \texttt{teachpop}, as they are defined by the same variable.

\begin{verbatim}
pred["teachpop", c("popular","sex","texp")] <- c(4,3,1)
pred["texp", c("popular","sex","teachpop")] <- c(4,3,4)
\end{verbatim}

Following the recipes, we should also include the interaction between
the group mean of teachpop and texp. However, when we tried this,
convergence issues became evident, as indicated by the trace plot (not
shown). Consequently, we decided to exclude this interaction term from
the imputation model.

We employ the obesity dataset included in the \pkg{micemd} package, a
simulated dataset that emulates an electronic survey in which
individuals are asked to provide information about their weight and
consumption habits in different countries. We use the following
variables from the dataset:

\begin{itemize}
\tightlist
\item
  \textbf{Cluster}: region of the patients' healthcare provider,
\item
  \textbf{Gender}: subjects' Gender (0=male, 1=female),
\item
  \textbf{Age}: subjects' age,
\item
  \textbf{Height}: subjects' height in metres,
\item
  \textbf{Weight}: subjects' weight in kilograms,
\item
  \textbf{BMI}: subjects' body mass index,
\item
  \textbf{FamOb}: family obesity history (yes or no),
\item
  \textbf{Time}: response time in minutes (exclusion-restriction
  variable).
\end{itemize}

In this dataset, \texttt{Age} and \texttt{FamOb} are MAR, while the
\texttt{Weight} variable is affected by selection bias, which we assume
to be caused by an indirect MNAR mechanism. This MNAR mechanism
typically arises when an unobserved or omitted variable influences both
the value of the incomplete variable (in this case, \texttt{Weight}) and
its likelihood of being missing.

In the main analysis model, BMI serves as the dependent variable, with
\texttt{Age}, \texttt{Gender}, and \texttt{FamOb} as predictors. Because
of the clustered nature of the data, we include random intercepts, as
well as random slopes for the \texttt{Age} variable. Therefore, the
model for the \(i\)-th region and the \(j\)-th subject is represented
as:

\begin{equation}
\label{eqn-main}
BMI_{ij}= (\beta_{o}+ b_{oj} ) + (\beta_{1}+ b_{1j})* Age_{ij} + \beta_{2}*FamOb_{ij}+ \beta_{3}Gender_{ij} + \epsilon_{ij}
\end{equation}

\noindent where \(\beta_0\), \(\beta_1\), \(\beta_2\), and \(\beta_3\)
are the fixed effects, \(b_{0i}\) and \(b_{1i}\) are the random
intercept and age slope effects distributed as
\(\begin{bmatrix}b_0\\b_1\end{bmatrix}\sim N\left(\begin{bmatrix}0\\0\end{bmatrix},\begin{bmatrix}\tau_0^2 & \rho\tau_0\tau_1\\\rho\tau_0\tau_1 & \tau_1^2\end{bmatrix}\right)\),
where we denote \(\tau_0^2\) and \(\tau_1^2\) for the intercept and
slope variances and \(\rho\) the correlation of the random effects. The
error term \(\epsilon_{ij}\) is normally distributed as
\(\epsilon_{ij}\sim N(0,\sigma^2)\), with variance \(\sigma^2\).

\hypertarget{imputation-3}{%
\subsubsection{Imputation}\label{imputation-3}}

In this example, we opt to use the 2L imputation methods from the
\pkg{micemd} package, which facilitate the imputation of incomplete
variables under sporadic and systematic missingness. Within this
package, various methods are available, including the 2l.stage methods
\cite{audigier2018}, where model estimation is conducted in two stages.

This package provides the \code{find.defaultMethod} function, which
recommends a suitable imputation method for MAR variables based on
variable type, cluster size, and number of clusters. Here, we apply this
function to provide an imputation method for all incomplete variables,
including the cluster variable position in the dataset
(\code{ind.clust = 1}) and using the function's default parameters.

\begin{verbatim}
library("micemd")
meth_mar <- find.defaultMethod(Obesity,
                               ind.clust = 1, I.small = 7,
                               ni.small = 100, prop.small = 0.4)
\end{verbatim}

It suggests using `2l.2stage.bin' for the FamOb variable and
`2l.2stage.norm' for the \texttt{Age} variable. However, upon inspecting
the density plot for \texttt{Age}, we found the variable to be highly
skewed, prompting us to consider modifying its method to
`2l.2stage.pmm'. For the BMI variable, we employ deterministic
imputation.

\begin{verbatim}
meth_mar["Age"] <- "2l.2stage.pmm"
meth_mar["Weight"] <- "2l.2stage.pmm"
meth_mar["BMI"] <- "~I(Weight/(Height)^2)"
\end{verbatim}

For these imputation methods, it is necessary to specify a prediction
matrix, with the cluster variable labelled as -2. However, here the
recipe that we used before is not longer necessary as these methods
assume that all the imputation models contains also a random slope
effect, so they use imputation Code 2 instead. We need to suppress the
variable \texttt{Time} as this variable is not specified in the main
model. We also modify the relationship between \texttt{BMI},
\texttt{Weight} and \texttt{Height} in the prediction matrix to avoid
circularity issues.

\begin{verbatim}
pred_mar <- make.predictorMatrix(Obesity)
pred_mar[, "Time"] <- 0
pred_mar[, "Cluster"] <- -2 
pred_mar[pred_mar == 1] <- 2
pred_mar[c("Height", "Weight"), "BMI"] <- 0
\end{verbatim}

Then we proceed to run the imputation model, using as visit order the
variables order according to their missing percentage.

\begin{verbatim}
imp_mar <- mice(data = Obesity,
                method = meth_mar,
                predictorMatrix = pred_mar,
                visit = c("Height","FamOb","Age","Weight","BMI"),
                printFlag = FALSE)
\end{verbatim}

We consider the possibility that patients may not have been selected
randomly, which would then have led to a distribution for weight that
does not reflect the weight in the population. It's likely that an
omitted variable, like self-esteem, could influence this selection. For
example, individuals with lower self-esteem might have higher weight
values, which would affect their willingness to provide honest
information as they feel embarrassed.

To address this situation where data are missing not at random (MNAR),
one approach is to apply the Heckman selection model \cite{munoz2023b}.
This method has recently been extended to allow for variations in
intercepts and exposure effects (random intercept and slope)
\cite{galimard2018, munoz2023}. This method involves specifying two
equations: one for the outcome, describing the incomplete variable in
terms of partially observed predictors (in this case, all variables from
the main model), and the other for the selection model, explaining the
probability of being observed based (denoted here as R) on certain
variables.

With this method, the \texttt{Weight} variable should be specified as
\code{2l.2stage.heckman}.

\begin{verbatim}
meth_mnar <- meth_mar
meth_mnar["Weight"] <- "2l.2stage.heckman"
\end{verbatim}

Additionally, the prediction matrix needs modification, as this model
includes one submodel for the individuals' measured outcome, and one for
the selection of individuals.

For the outcome equation we consider the same imputation model that we
used for the MAR case (main model).
\[Weight_{ij}= \beta^O_{o} + \beta^O_{1}Age_{ij} + \beta^O_{2}FamOb_{ij}+ \beta^O_{3}Gender_{ij} + \epsilon^O_{ij}\]
Regarding the selection equation, we include the same predictors as
those in the main model, as well as a time variable. Here the time
variable serves as a restriction exclusion variable specifically
explaining the probability of being observed but not affecting the
incomplete value (Weight). In this context, we assume that the time a
user spends completing the survey serves as a proxy for the barriers
they may encounter in survey completion, such as familiarity with the
survey content or internet speed. These factors may lead the user to
skip specific questions or even the entire survey. Also, we assume the
time does not have any influence on the subject's weight.
\[R_{ij}= \beta^S_{o} + \beta^S_{1}Age_{ij} + \beta^S_{2}FamOb_{ij}+ \beta^S_{3}Gender_{ij} +\beta^S_{4}Time_{ij}+ \epsilon^S_{ij}\]

These two equations are jointly estimated under the assumption that the
error terms are interconnected with a bivariate normal distribution. For
a more comprehensive understanding of the model and the exclusion
restriction, see \cite{munoz2023}.

To use information from both equations, we must adjust the prediction
matrix. The cluster variable remains specified as before (-2). In this
imputation method, all the variables present in both the selection and
outcome equations are included with a random effect.

However, it is essential to distinguish which of these variables appear
in each equation. In this framework, when a variable is shared between
both equations, it is denoted as (2). Predictors exclusive to the
outcome equation are indicated as (-4), while those exclusive to the
selection equation are labelled as (-3). Consequently, the only
alteration needed in the predictor matrix pertains to the variable
\texttt{Time}. Predictor matrices of both scenarios (MAR and MNAR) are
displayed in Figure \ref{fig-obs4_5}:

\hypertarget{conclusion}{%
\section{Conclusion}\label{conclusion}}

In this paper we explored the imputation process for incomplete
multilevel datasets, with a primary focus on utilizing a hierarchical
model for analysis. We encourage users to consider insights provided by
domain experts, to gain a better understanding of variable relationships
and to chose the most appropriate imputation strategy to follow. This
includes considerations of the (primary) research question and the
corresponding data analysis, as the imputation strategy needs to be
compatible with the data analysis. Employing clear data visualization is
instrumental in comprehending the missing data patterns, investigating
the likely missingness mechanism, and aiding in the selection of
suitable imputation methods.

The \pkg{mice} and \pkg{mice}-based R packages offer a range of
imputation methods tailored for hierarchical data, easily adaptable to
the dataset's structure. Before proceeding with the analysis of the
imputed dataset, it is essential to assess the convergence of the
imputation method. This evaluation can reveal issues such as circular
dependencies, the need for additional iterations, or challenges
associated with the chosen imputation method.

            mod_tab <- mod_tab[, c("term", "estimate", "conf.low", 
                "conf.high", "p.value")]
            rownames(mod_tab) <- NULL
            varcomp <- insight::get_variance(mod)
            vartable <- data.frame(Term = "Residual variance", 
                Value = as.numeric(varcomp$var.residual))
            if (!is.null(varcomp$var.intercept)) {
                vartable <- add_row(vartable, Term = "Random intercept\nvariance", 
                  Value = as.numeric(varcomp$var.intercept))
            }
            if (!is.null(varcomp$var.var.slope)) {
                vartable <- add_row(vartable, Term = paste0("Random slope var", 
                  attr(varcomp$var.slope, "names")), Value = as.numeric(varcomp$var.intercept))
            }
            if (!is.null(varcomp$cor.slope_intercept)) {
                vartable <- add_row(vartable, Term = paste0("Random slope-intercept corr", 
                  attr(varcomp$cor.slope_intercept, "names")), 
                  Value = as.numeric(varcomp$cor.slope_intercept))
            }
            if (!is.null(varcomp$var.intercept)) {
                vartable <- add_row(vartable, Term = "ICC", Value = as.numeric(varcomp$var.intercept)/(as.numeric(varcomp$var.intercept) + 
                  as.numeric(varcomp$var.residual)))
            }
        }
        colnames(mod_tab) <- c("Coefficient", "Estimate", "lower", 
            "upper", "p.value")
        mod_tab$model <- mod_name[i]
        mod_table <- rbind(mod_table, mod_tab)
        vartable$model <- mod_name[i]
        var_table <- rbind(var_table, vartable)
    }
    plot_coef <- ggplot(mod_table, aes(x = Coefficient, y = Estimate, 
        ymin = lower, ymax = upper, group = model, color = model)) + 
        geom_hline(yintercept = 0, linetype = "dashed", color = "black", 
            size = 0.1) + geom_linerange(position = position_dodge(width = 0.8)) + 
        geom_pointrange(size = 0.1, position = position_dodge(width = 0.8)) + 
        coord_flip() + theme_classic() + theme(legend.position = "bottom")
    +scale_color_viridis_d()
    if (randisplay == T) {
        var_table <- filter(var_table, str_detect(Term, "^Random"))
    }
    plot_var <- ggplot(var_table, aes(x = Term, y = Value, fill = model)) + 
        geom_bar(stat = "identity", position = "dodge") + coord_flip() + 
        scale_fill_viridis_d() + xlab("Term") + ylab("Estimate") + 
        theme_light() + theme(legend.position = "bottom")
    return(list(plot_coef, plot_var))
}

\hypertarget{sec-bibtex}{%
\section*{Using BibTeX}\label{sec-bibtex}}
\addcontentsline{toc}{section}{Using BibTeX}

\begin{tcolorbox}[enhanced jigsaw, bottomrule=.15mm, leftrule=.75mm, arc=.35mm, rightrule=.15mm, breakable, colback=white, left=2mm, opacityback=0, toprule=.15mm]

References need to be provided in a \textsc{Bib}{\TeX} file
(\texttt{.bib}). All references should be made with \texttt{@cite}
syntax. This commands yield different formats of author-year citations
and allow to include additional details (e.g.,pages, chapters, \dots) in
brackets. In case you are not familiar with these commands see the JSS
style FAQ for details.

Cleaning up \textsc{Bib}{\TeX} files is a somewhat tedious task --
especially when acquiring the entries automatically from mixed online
sources. However, it is important that informations are complete and
presented in a consistent style to avoid confusions. JSS requires the
following format.

\begin{itemize}
\tightlist
\item
  item JSS-specific markup (\texttt{\textbackslash{}proglang},
  \texttt{\textbackslash{}pkg}, \texttt{\textbackslash{}code}) should be
  used in the references.
\item
  item Titles should be in title case.
\item
  item Journal titles should not be abbreviated and in title case.
\item
  item DOIs should be included where available.
\item
  item Software should be properly cited as well. For \proglang{R}
  packages \texttt{citation("pkgname")} typically provides a good
  starting point.
\end{itemize}

\end{tcolorbox}
